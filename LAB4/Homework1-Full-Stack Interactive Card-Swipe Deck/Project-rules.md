3. Assignment scope and lecture contracts
The Lab 4 specification names this assignment Full-Stack Interactive Card-Swipe Deck, 'Hen Ho Nhung Khong Yeu' Edition. It is labelled Homework 1 on the specification slide and Homework 4 on the frontend/backend code-contract slides (printed slides 31 and 32). Homework 1.2 is our local naming convention, not an official slide label.

The four required features are: - Dual keyboard/pointer event listeners for responsive swipe queue operations. - LIFO undo stack that restores swiped cards in reverse order. - Asymmetric score calculated as derived state, not independently stored score state. - Full-stack persistence using Express and Mongoose 8 with async/await.

The frontend examples name SwipeDeck.jsx, SwipeListeners.jsx and SwipeState.jsx. ArrowLeft invokes swipe('left'), ArrowRight invokes swipe('right'), ArrowUp invokes swipe('up'), and Backspace invokes undoLastSwipe(). The pointer example records clientX/clientY on pointer down and uses horizontal displacement greater than 50 or less than -50 on pointer up. The history example removes the last action with slice(0, -1). The score example reduces history, adding 10 for LIKE and subtracting 5 for every other action. Preserve this formula unless I provide a different lecturer requirement. The example does not define the business meaning of every direction; document a consistent mapping before implementation (proposed: right = LIKE, left = PASS, up = SUPER_LIKE, with the latter scoring -5 under the literal example). Explain that choice rather than silently changing the formula. The vertical pointer gesture, threshold and diagonal policy are implementation decisions, not explicit lecture requirements; propose a consistent policy for keyboard/pointer parity.

The backend examples require a MONGODB_URI environment guard, await mongoose.connect(process.env.MONGODB_URI), GET /api/profiles using Profile.find().lean(), and POST /api/swipe using Swipe.create with a 201 response or a handled 400 error. Do not use removed Mongoose callbacks or deprecated useNewUrlParser/useUnifiedTopology options. Use Mongoose 8 explicitly. Validate input before persistence and distinguish validation errors from server failures. Do not implement unrelated Photo Gallery, tribunal, authentication or production deployment.

The slides do not define a complete schema, undo persistence endpoint, session identity, seed dataset or reload policy. Before coding, document these as design decisions. Propose a minimal coherent contract: stable profile IDs, action enum, persisted ordered swipe history scoped to a demo session, a history read endpoint and a last-action undo endpoint if needed for reload consistency. Explain these additions as proposed, not lecturer-mandated endpoints. Ensure the visible queue, history and score agree with persisted actions after undo and reload. Use a simple serialized mutation policy, prevent duplicate actions and recover from failed requests without falsely showing success. Use a small clearly fictional seed dataset if no profiles exist, with no real personal data. Do not assume MongoDB is installed or running; help me choose an available local instance or Atlas without exposing credentials.
